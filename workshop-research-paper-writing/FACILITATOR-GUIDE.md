# Facilitator Guide

**Workshop:** Research Paper Writing and Research Tools — From Research Idea to Journal Publication
**Duration:** 2 days (approx. 7 contact hours per day)
**Audience:** PhD scholars, research scholars, PG students, early-career researchers
**Decks:** `slides/day1.md` (69 slides), `slides/day2.md` (46 slides) — 115 slides total

This guide lets a faculty member or senior scholar deliver the full workshop without developing content. Speaker notes are embedded in the decks themselves (visible in presenter mode, in the notes-enabled PDF, and in the PPTX notes pane); this document covers **timing, logistics, demo scripts, contingencies, and assessment**.

---

## 1. Before the workshop

### 1.1 Facilitator preparation (about 4 hours)

| Task | Detail |
|---|---|
| Read both decks with speaker notes | The notes carry the pedagogy, not just reminders |
| Choose **your** demo topic | Replace the chest-radiograph example with a topic from your own field if you can teach it fluently. The deck's example is deliberately self-contained so you *can* use it as-is |
| Pre-run all 7 live demos | Section 2.3 below. Log in to every platform in advance |
| Capture fallback screenshots | Save to `assets/screenshots/`. Assume the network will fail at least once |
| Select 2 open-access papers | One for the timed Pass-1 triage demo (S4), one for the extraction demo. Use papers your participants' field will recognise; confirm they are freely accessible |
| Prepare 3 synthetic reviewer comments | For Activity 24.1. One easy, one requiring a new experiment, one that should be pushed back on. A worked set is in `handouts/reviewer-response-template.md` |
| Check institutional access | Note which of Scopus / Web of Science / IEEE Xplore / ACM DL your institution can reach, and prepare the free-tool substitutions |
| Decide assessment mode | Credit-bearing (use the rubrics) or participation-only |
| Print/share handouts | Six files in `handouts/`. Sharing the folder link is enough if participants have laptops |

### 1.2 Participant pre-work (send 5–7 days ahead)

Send this verbatim:

> To get value from the workshop you must arrive with a laptop and the following ready:
> 1. **A topic.** One research area you are working in or want to work in. Not a finished plan — a direction.
> 2. **Library access.** Test your institutional login / VPN for Scopus, Web of Science, IEEE Xplore and ScienceDirect *before* Day 1. Tell us if you have no access; free alternatives will be used.
> 3. **Zotero installed** (zotero.org) with the browser connector and the Word/LibreOffice plugin.
> 4. **An Overleaf account** (free tier is fine).
> 5. **A Google account** for Google Sheets, or Excel installed.
> 6. **5–10 PDFs** of papers in your area that you have already downloaded (they do not need to be read).
> 7. Optional but useful: access to your institution's Turnitin/iThenticate, and any AI assistant you already use.
>
> Day 1 is search, reading and gap analysis. Day 2 is writing, ethics and publication. You will build your own artefacts throughout — the workshop is not a lecture.

### 1.3 Room and materials

- Projector with a **wide screen** (slides are 16:9 and table-dense; test legibility from the back row)
- Reliable Wi-Fi for participants; a mobile hotspot as backup for the facilitator
- Whiteboard or flip chart — used in S1, S2, S5, S7 for live narrowing and critique
- Visible countdown timer (phone/browser timer projected during activities)
- Power strips (activities run 45–100 minutes)
- Optional: sticky notes for topic collection in the first hour

**Day 2 is over-subscribed by design.** Two viable compressions:

### 2.3 Live demo scripts

Each demo has a fallback. Announce which tools are free and which need a subscription every time.

| # | Slide | Demo | Steps | Fallback |
|---|---|---|---|---|
| 1 | S2 (21) | Emerging topics | (a) A benchmark leaderboard: show a flattened metric curve → "flattening is an opportunity". (b) OpenReview: open a recent accepted paper, expand reviews, read one weakness aloud → "that is a peer-endorsed gap". (c) Connected Papers: paste a DOI, show Prior/Derivative tabs | Screenshots; OpenReview and Connected Papers are free and usually reachable |
| 2 | S3 (31) | Build the search string | Paste concept block C1 alone → note the count. Add C3 → count. Add C4 → count. Add year + doctype → count. Then **Analyze search results** → Documents by year / source / author. Then Export → RIS → import to Zotero | Run the free Semantic Scholar + OpenAlex versions; `api.openalex.org/works?search=...` works in a browser with no key |
| 3 | S3 (33) | Citation chaining | On one paper: open reference list (backward), Scholar "Cited by" + "search within citing articles" (forward), Connected Papers graph (sideways). Then create an email alert | Screenshots; Scholar is free |
| 4 | S4 (37) | **Timed Pass-1 triage** | Open your chosen OA paper. Project a 7-minute countdown. Narrate every decision: title/venue → abstract → Fig. 1 → all tables → headings → conclusion → references. Then show your 5-line triage note | Use a locally saved PDF — this demo needs no network |
| 5 | S6 (51) | Zotero → Sheets matrix | Drag a PDF into Zotero → show retrieved metadata → **deliberately fix a wrong field** → add a colour tag → child note from the template → Export Collection as CSV → open in Sheets → freeze row 1 → add filter → conditional-format the split column → live-type `=COUNTIF(E2:E16,"*random*")` and show the tally appear | All local + free; no network needed after install |
| 6 | S19 (26) | Zotero → Overleaf → DOI check | Better BibTeX auto-export to `refs.bib` → Overleaf IEEEtran template → upload `.bib` → `\cite{}` → compile → then paste one DOI into `doi.org` and compare fields side by side | Screenshots; Overleaf free tier is enough |
| 7 | S20 (29) | **The citation-verification demo** | Ask an LLM for "five recent papers on <topic> with DOIs". Attempt to resolve each DOI at `doi.org` live. Whatever happens, draw the lesson: fabricated/mismatched entries prove the risk; correct entries prove verification is cheap | Pre-captured transcript + resolution attempts |
| 8 | S22 (37) | Journal verification | Run the 10-step sequence on one legitimate journal in the participants' field: publisher site → Clarivate Master Journal List → Scopus Sources → Scimago → DOAJ → ISSN Portal → COPE → editorial board spot-check → read two recent papers. Then run it on a real solicitation email (redacted) until it fails | Screenshots. MJL, Scimago, DOAJ, ISSN Portal and COPE are all free |

### 2.4 Facilitation habits that make this workshop work

1. **Collect topics in the first hour.** Sticky notes or a shared chat. Sanity-check scope early so the Section 2 clinic can use real examples.
2. **Use participants' topics, not the deck's, for every live narrowing.** The deck example is a safety net.
3. **Walk the room during every activity.** Ask one question per participant, chosen from the notes for that activity.
4. **Timebox visibly.** Project the countdown. Activities silently expand otherwise.
5. **Ask "how do you know?" three times** whenever a participant asserts a gap.
6. **Celebrate discovered infeasibility.** A participant who learns on Day 1 that their plan needs 500 GPUs has gained a year.
7. **Never rescue a weak example anonymously-but-recognisably.** Ask permission before discussing anyone's topic publicly.
8. **Model the professional register** in every critique: specific, evidence-based, about the work and never the person.

## 3. Adapting for non-CS disciplines

The structure is discipline-neutral; only S14–S17 need translation. Announce this openly in the Day 1 outcomes so non-CS participants do not disengage.

| Deck concept | Management / social science | Life / health sciences | Education | Engineering (non-CS) |
|---|---|---|---|---|
| Dataset | Sample, population, sampling frame | Cohort, specimens, registry | Participants, schools, cohorts | Test specimens, simulation cases |
| Split protocol / leakage | Clustering by firm/region; unit of analysis | Patient-level, site-level, temporal splits | Classroom/school-level clustering | Batch/specimen independence |
| Preprocessing | Data cleaning, coding, scale construction | Inclusion/exclusion, imputation | Instrument scoring | Calibration, filtering |
| Baseline | Comparison group; existing theory/model | Standard of care; control arm | Business-as-usual condition | Conventional design/material |
| Ablation | Hierarchical regression steps; sensitivity | Sensitivity/subgroup analysis | Component analysis of intervention | Parametric study |
| Metrics (S16) | Validity, reliability (Cronbach α, ICC), effect size (d, η²), fit indices | Sensitivity/specificity, NNT, HR, CI | Effect size, gain scores, reliability | Error, tolerance, factor of safety |
| Reproducibility | Codebook, syntax files, data deposit | Protocol registration, CONSORT/STROBE | Protocol, instruments deposited | Test standards, calibration records |
| Reporting standards | — | CONSORT, STROBE, PRISMA, CONSORT-AI | — | Relevant ISO/ASTM standards |
| Qualitative work | Saturation, member checking, audit trail, intercoder agreement (κ), COREQ/SRQR | Same | Same | — |

For a **qualitative-heavy audience**, replace S16 entirely with: trustworthiness criteria (credibility, transferability, dependability, confirmability), coding reliability, saturation, reflexivity, and the COREQ/SRQR checklists. Keep everything else unchanged — the gap logic, matrix, writing structure, ethics and publication mechanics are identical.

## 5. Contingencies

| Problem | Response |
|---|---|
| No Scopus/WoS access | Run everything on Semantic Scholar + OpenAlex + Google Scholar + arXiv + DOAJ. Show the Scopus syntax anyway as the reference grammar, then port it live |
| Network down | Demos 4 and 5 work offline. Use screenshots for the rest. Convert freed time into activity time |
| Participants arrive with no topic | Give them one from a prepared list of 6 (one per common department), each already narrowed to the "one-breath" level. They still do all activities |
| Mixed levels | Pair a novice with an experienced participant for every activity; give the experienced ones the extra task of critiquing their partner's gap against the 12 gap types |
| Group too large for individual attention (>40) | Form fixed table groups of 4; run all pair work within tables; collect one deliverable per table for public debrief |
| Only 1 day available | Deliver Day 1 S1–S7 (drop S8) plus Day 2 S9–S13 and S20–S21. Assign the matrix as pre-work rather than an in-session activity |
| Participants want the slides | Share the repository. The Markdown is the source of truth; PDF/PPTX are generated |

## 6. Building the decks

```bash
npm install

# PDF/PPTX need a Chromium-family browser:
export CHROME_PATH=/usr/bin/google-chrome   # or /usr/bin/chromium
export CHROME_NO_SANDBOX=1                  # only when running as root / in a container

npm run html     # build/day1.html, build/day2.html  (presenter mode: press P)
npm run pdf      # build/*.pdf  — includes speaker notes as PDF notes
npm run pptx     # build/*.pptx — speaker notes land in the PowerPoint notes pane
npm run build    # all three
```

On a minimal Linux install, also install `dejavu-sans-fonts` and `dejavu-sans-mono-fonts`; without a font that covers arrows (→) and box-drawing characters, the flow diagrams render as empty boxes.

Presenting from HTML gives the best experience: open `build/day1.html`, press **P** for the presenter view with notes and a timer.

To edit content, edit the Markdown — never the generated files. Slides are separated by `---`; text inside `<!-- ... -->` becomes speaker notes.

## 7. Content maintenance

Review these before each delivery; they change:

- **Platform syntax** (Scopus field codes, IEEE Command Search, ScienceDirect operator limits) — verify on each platform's help page and update S3
- **Tool names, features and pricing** in S20 — the *functional* classification is stable; the products are not
- **Journal metrics** (JIF/CiteScore definitions and release cycles) in S22
- **AI-use and preprint policies** of major publishers in S20/S21 — these have been changing yearly
- **Your institution's** integrity policy, similarity threshold, AI policy, and degree publication requirements — name them explicitly rather than speaking generically

### A note on the worked examples

The chest-radiograph domain-generalisation study (papers "P1–P10", the method "CLUSTER-DG", and all numeric results) is an **illustrative composite built for teaching**. It is realistic but not real. Named public works and datasets (ResNet, DenseNet, ViT, CORAL, IRM, CheXpert, MIMIC-CXR, NIH ChestX-ray14, PadChest) are referenced as examples of *type*; dataset statistics on the slides are approximate and must be verified against each dataset's own documentation before use.

Say this out loud at least twice — once at slide 2 of Day 1 and once during the extraction worked example. Participants will otherwise copy example citations into their own drafts, which is exactly the behaviour the workshop teaches against.
